# OLIVE ポータルサイト

おかやま地域未来共創プラットフォーム（OLIVE）の公式サイトです。

**公開URL：** `https://<ユーザー名>.github.io/<リポジトリ名>/`

---

## 📝 お知らせを追加する（いちばんよく使う操作）

**`news.js` だけを編集すれば、トップページと「お知らせ」ページの両方が同時に更新されます。**
HTMLファイルを触る必要はありません。

### 手順

1. このページのファイル一覧から **`news.js`** をクリック
2. 右上の **鉛筆マーク（✏️ Edit this file）** をクリック
3. `var NEWS = [` のすぐ下に、次のかたまりを貼り付けて書き換える

```js
  {
    date:  "2026.09.15",
    tag:   "イベント",
    title: "第1回おかやま未来創生ユース会議を開催しました。",
    url:   ""
  },
```

4. 右上の緑のボタン **「Commit changes」** → もう一度 **「Commit changes」**
5. **1〜2分待つ**とサイトに反映されます

### 書き方のルール

| 項目 | 意味 | 例 |
|---|---|---|
| `date` | 表示される日付。書き方は自由 | `"2026.09.15"` `"2026.09"` `"準備中"` |
| `tag` | 右端の小さなラベル | `"お知らせ"` `"記者発表"` `"採択"` `"資料公開"` `"イベント"` `"募集"` `"報道"` |
| `title` | 一覧に出る文章 | `"○○を開催しました。"` |
| `url` | リンク先。**なければ `""` のまま** | `"https://www.sanyonews.jp/..."` |

⚠️ **つまずきやすいところ**

- `"` （ダブルクォート）で囲むのを忘れない
- 行の終わりの `,` （カンマ）を消さない
- `}` の後ろにも `,` を付ける（いちばん最後の1件だけは無くてもOK）
- 文章の中で `"` を使いたいときは、代わりに `「 」` を使う

**新しい記事ほど上に書きます。** トップページには上から3件だけ自動で表示されます。

## 📰 Wordで書いた記事を公開する

**Wordの原稿を、サイトと同じデザインの記事ページに自動変換するツールを用意しています。**

### ツールのURL

```
https://<ユーザー名>.github.io/<リポジトリ名>/convert.html
```

このページはナビゲーションに載せておらず、**検索エンジンにも表示されません**（noindex設定済み）。**ブックマークしておいてください。**

変換はすべてブラウザの中で完結し、原稿がどこかに送信されることはありません。またこのページを他人が開いても、**自分のパソコンにファイルをダウンロードできるだけで、サイトを書き換えることはできません**（公開にはGitHubへのログインが必要）。

### 手順

1. **Wordで記事を書く**
   - 1行目にタイトルを書き、**スタイルを「表題」または「見出し1」**にする
   - 本文中の小見出しも**「見出し1」**を使う
   - 箇条書き・表・太字・画像はそのまま使えます
2. ファイル名を **`2026-09-15-ユース会議.docx`** のように、**先頭に日付**を入れて保存
3. 上のURLを開き、**Wordファイルをドラッグ**
4. 日付・ラベル・タイトルが自動で入るので、必要なら直す
5. **プレビューで仕上がりを確認**
6. **「記事ファイルをダウンロード」**→ `article-20260915.html` が保存される
7. GitHubで **「Add file」→「Upload files」**して、そのファイルをアップロード
8. 画面に出ている **news.js用のコード**をコピーし、`news.js` の `var NEWS = [` の下に貼り付ける

これで一覧にも記事が並び、クリックすると記事ページが開きます。

### Wordを書くときのコツ

| Wordでの操作 | サイトでの見え方 |
|---|---|
| スタイル「表題」「見出し1」（1行目） | 記事タイトル |
| スタイル「見出し1」（本文中） | 大見出し（下線つき） |
| スタイル「見出し2」 | 中見出し（オリーブ色） |
| 箇条書き | ● リスト |
| 表 | 罫線つきの表 |
| 太字 | **太字** |
| 貼り付けた画像 | 記事内の写真として表示 |

⚠️ **画像はWordに貼り付けたものがそのまま記事ファイルに埋め込まれます。** 大きな写真を何枚も入れるとファイルが重くなるので、1記事あたり2〜3枚を目安にしてください。

⚠️ 文字色・フォント・インデントなどの細かい書式は、**サイトのデザインに統一されます**（Wordの見た目そのままにはなりません）。これは意図的な仕様です。

## 📂 記事が増えてきたときの管理

### 結論：しばらくは「フォルダを作らない」のがおすすめです

現在の構成は、すべてのファイルが同じ階層に並ぶ**フラット構成**です。
一度フォルダ（`assets/`）で失敗しているとおり、**GitHubのアップロード画面はフォルダ構造が崩れやすい**ため、フォルダを増やすとリンク切れの原因になります。

記事ファイルは `article-20260915.html` のように**日付が入った名前**なので、GitHubのファイル一覧では自動的に日付順に並びます。**年に数本〜十数本のペースなら、これで十分に管理できます。**

### Word原稿は GitHub ではなく Google ドライブへ

**GitHubには「公開するもの」だけを置き、Word原稿は今まで通り Google ドライブ（`マイドライブ/2_OLIVE`）で管理することをおすすめします。**

| 置き場所 | 入れるもの |
|---|---|
| Google ドライブ | Word原稿、写真の元データ、下書き |
| GitHub | 公開されるHTML・CSS・画像だけ |

理由は3つあります。

- GitHubのリポジトリは **Public（誰でも閲覧可能）** なので、未公開の下書きを置くべきではない
- Word原稿は編集履歴・共同編集ともにGoogleドライブのほうが扱いやすい
- GitHubにフォルダを作らずに済む

### 記事が50本を超えたら

ファイル一覧が長くなって探しにくくなったら、そのタイミングで
`2026/` `2027/` のような年別フォルダへの整理をご相談ください。
**リンクの書き換えが必要になるため、こちらで一括対応します。**

## 🖼 写真を差し替える

同じファイル名で上書きすれば、そのまま入れ替わります。

1. **「Add file」→「Upload files」**
2. 差し替えたい画像を**同じファイル名**にしてからアップロード
3. Commit changes

| ファイル名 | 使われている場所 |
|---|---|
| `kodai-workshop.jpg` | トップページ |
| `univ-network.jpg` | OLIVEとは |
| `roundtable.jpg` | あなたにとってのOLIVE |
| `olive-wreath.jpg` | メンバー |
| `fieldwork.jpg` | 4つの取組（上） |
| `dx-class.jpg` | 4つの取組（下） |

💡 画像は**横1600px程度・300KB以下**が目安です。大きすぎるとページが重くなります。

⚠️ 現在の写真はすべてAI生成のイメージ画像で、キャプションにその旨を記載しています。実際の活動写真に差し替えた際は、`※ 本画像は活動のイメージです。` の一文を削除してください。

## 🎨 デザインを変える

- `style.css` … 色・文字サイズ・余白
- `site.js` … 動き（アニメーション）

色を変えたい場合は `style.css` の先頭にある変数を書き換えます。

```css
--navy:#0a5ba8;      /* 濃い青 */
--olive:#7fa33e;     /* オリーブ色 */
--olive-deep:#4f6329;/* 濃いオリーブ */
```

## 🔄 元に戻したい / 失敗したとき

**GitHubは変更履歴がすべて残るので、いつでも元に戻せます。安心して編集してください。**

1. 上部の **「コミット」（Commits）** をクリック
2. 戻したい時点の変更を選ぶ
3. 右上の **「…」→「Revert」** で取り消し

## ⏱ 反映されないとき

- **1〜2分待つ**（GitHubがページを作り直す時間が必要です）
- それでも古いままなら **`Ctrl + F5`**（Macは `Cmd + Shift + R`）で強制再読み込み
- 上部の **「Actions」** タブに赤い ✗ が出ていないか確認
